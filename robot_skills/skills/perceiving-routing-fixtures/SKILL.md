# Measure the routing fixtures

Segment and fit the fixture geometry, then publish the measured scene and station count. Scene is a JSON string carrying these measured values; consumers must decode it without consulting simulator object state.

This is the starting point of the vision-only weave graph. Easy and Medium use the same graph with different physical layouts.

For fixed-end Easy (two pegs) and Medium (four pegs), use only the fixed third-person cable RGB-D camera for fixture detection, centreline tracking, grasp refinement, terminal placement, and verification. Do not use overhead or wrist fallbacks; if the cable view is occluded, retain the measured prior or report lost evidence.

## Routing cases

| Case | Task | Layout |
| --- | --- | --- |
| Easy | `cable_route/port_easy` | 2 pegs, 1 cable, `end_a` physically fixed at the anchor, `end_b` routed into the port |
| Medium | `cable_route/port_medium` | 4 pegs, 1 cable, `end_a` physically fixed at the anchor, `end_b` routed into the port |

Both cases use this same skill contract in the `graphs/weave` workflow. The crossing loop follows the perceived stations: two for Easy, four for Medium. The destination port sits beyond the last peg, opposite the anchored start.

Compose the example subgraph using its declared inputs and route every exit, including `on_error`. A normal exit describes the node's observation or completed command; only the separate settled task evaluator determines benchmark success.

Use RGB-D observations and robot proprioception for the evaluated vision path. Oracle recipes and privileged survey probes are for diagnostics; the vision path must work with those tools withheld (`--perception vision --no-privileged`).

Grippers act through commanded joints and contact friction. Do not introduce object teleports, grasp welds, cable latches, retention forces, or suppressed fixture collisions. The physical cable attachment and fixed bench anchor belong to the scene.

These recipes require the RoboSimStudio connector; they are not a claim of hardware portability. SAM3 calls require the deployed segmentation tool and its weights.

This bundle is generated by `tools/sync_robot_skills.py`. Edit strategy in `robot_skills/catalog.json` and recipes in the source graph, then regenerate. Every Python helper needed by the canonical scripts is included. Export scopes sibling imports to the bundle package; the rest of each recipe is preserved.
