# Observe and track the cable centreline

Fit the fresh cable mask into an ordered polyline. When the fit is incomplete, use the prior observed curve and visibility-gated tracking. Store only perception-derived curves in cable.curve_memory.

Refine the local grasp from the camera evidence. Lost evidence raises the lost exit. No simulator centreline or point index may substitute for the measured shape. During the crossing loop, lost aborts. The final retrack may instead continue to terminal insertion, whose own vision helpers can attempt a fresh observation.

Fit depth only at pixels inside the cable mask, including after skeleton upsampling and rounding. Spline residuals are in squared metres: use the metric default (1 mm RMS). Establish the opening length from a curve consistent with the observed bench height before using it as the slack or tracking reference.

For fixed-end Easy (two pegs) and Medium (four pegs), use only the fixed third-person cable RGB-D camera for fixture detection, centreline tracking, grasp refinement, terminal placement, and verification. Do not use overhead or wrist fallbacks; if the cable view is occluded, retain the measured prior or report lost evidence. Before retaining the prior, clear the view rather than the estimator: when a hand stands low over the rod, step it behind the run and observe once more from the same camera. A retained prior is reported as such, so a crossing planned on a curve that predates the last one is visible in the trace rather than indistinguishable from a fresh read.

Filter segmented pixels by height above the bench measured from cable-camera depth before fitting. A plausible arc length is insufficient: reject fresh or tracked curves that extend through the table or up robot links. When only a fragment is visible, update the existing curve from the visible jacket instead of replacing it with that fragment.

| Easy | `cable_route/port_easy` | 2 pegs, 1 cable, `end_a` physically fixed at the anchor, `end_b` routed into the port |

Both cases use this same skill contract in the `graphs/weave` workflow. The crossing loop follows the perceived stations: two for Easy, four for Medium. The destination port sits beyond the last peg, opposite the anchored start.

Use RGB-D observations and robot proprioception for the evaluated vision path. Oracle recipes and privileged survey probes are for diagnostics; the vision path must work with those tools withheld (`--perception vision --no-privileged`).

Grippers act through commanded joints and contact friction. Do not introduce object teleports, grasp welds, cable latches, retention forces, or suppressed fixture collisions. The physical cable attachment and fixed bench anchor belong to the scene.
